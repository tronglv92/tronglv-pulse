## Project Overview

**Pulse** is an AI-native observability platform (portfolio project). It ingests logs over HTTP, detects anomalies via rolling z-score, generates AI-powered Root Cause Analysis (RCA) using Claude Sonnet, and streams live data via WebSocket. The core stack is Go + Kafka + Postgres (TimescaleDB + pgvector) + Redis.

## Commands

```bash
# Run services
make run        # API server: HTTP (8000) + gRPC (8001)
make ingest     # Ingest server: HTTP (8002)
make worker     # Kafka consumer worker
make cron       # Scheduled jobs service
make sim        # Synthetic log generator (traffic simulation)
air             # Live reload for the API server (uses .air.toml → cmd/api/main.go)

# Testing
make test       # Run all tests with coverage (excludes generated pb/mock files)
make coverage   # Generate coverage.html report
go test ./internal/service/... -run TestName -v  # Single test

# Code generation — run after editing .proto files
make grpc       # Regenerate gRPC + HTTP + OpenAPI from protos
make validate   # Regenerate protoc-gen-validate code
make mocks      # Regenerate mocks via mockery

# pmctl — internal codegen tool
# service_factory.go is generated by pmctl, never hand-edit it
# Re-run whenever you add/remove a service or repository:
pmctl gen service   # Regenerates internal/service/service_factory.go

# Tooling setup (first-time only)
make init       # Install goctl, protoc plugins, grpcurl
```

Config is loaded from `etc/{service}.yaml` with `${ENV_VAR}` substitution. Copy `.env.example` to `.env` before running locally.

Local dev stack (`docker-compose up`): TimescaleDB (Postgres 15 + pgvector), Redis 7, Kafka, Kafka UI.

## Architecture

### Five binary entry points

| Binary | Path | Purpose |
|---|---|---|
| API server | `cmd/api/main.go` | gRPC (8001) + REST (8000) + WebSocket |
| Ingest server | `cmd/ingest/main.go` | HTTP-only log ingestion (8002) |
| Worker | `cmd/worker/main.go` | Kafka consumers: enricher, rca, notify |
| Cron | `cmd/cron/main.go` | Scheduled background jobs |
| Sim | `cmd/sim/main.go` | Synthetic traffic generator for demos |

### Dependency injection via Registry

`internal/registry/` is the sole wiring layer — handlers and services never construct their own dependencies.

- **`ServiceContext`** — root context for the API server; composes `RepositoryContext` and vends `ServiceFactory`.
- **`RepositoryContext`** — holds GORM-backed repositories.
- **`ConsumerContext`** — narrower context for the Kafka worker.
- **`CronContext`** — narrower context for scheduled jobs.
- **`BaseContext`** — minimal interface (`GetConfig`, `GetDownloader`) embedded by all contexts.

Services inside `ServiceFactory` are lazy-initialized via `oncex.OnceValue` — created on first access, not at startup. `service_factory.go` is generated by `pmctl gen service` and must not be edited by hand.

### Request flow (HTTP)

Proto → `make grpc` → `api/{domain}/{domain}_http.pb.go` (routes generated by grpc-gateway) → registered in `internal/handler/http_handler.go` → handler calls `svc.GetServiceFactory().GetXxxService()`.

### Proto-first API design

- Proto files live in `api/{domain}/{domain}.proto` and shared types in `protos/`.
- `make grpc` emits `.pb.go`, `_grpc.pb.go`, `_http.pb.go`, and `openapi.yaml`.
- **Never hand-edit** `api/*/*.pb.go` or `api/*/*.pb.validate.go`.

### Data transformation: Mapper pattern

Mappers in `internal/types/mapper/{domain}.go` are the only place that converts GORM entities → proto response types.

```
entity.LogEntry  →  mapper.LogEntryMapToResponse()  →  logpb.GetLogResponse
```

- Entities live in `internal/types/entity/`
- Request/response DTOs live in `internal/types/dto/`
- Constants/enums live in `internal/types/define/`
- Domain events live in `internal/types/event/`

### Key infrastructure wrappers (`tronglv-pulse/helper/utils/`)

These helper packages are accessed via the `go.work` workspace during development:

| Package | What it wraps |
|---|---|
| `db/gorm` | GORM + primary/replica setup + auto-migration |
| `cache` | Redis via `go-redis/v9` |
| `queue` | Kafka (`segmentio/kafka-go`) or RabbitMQ, unified interface |
| `server` | go-zero HTTP + gRPC server builders |
| `toolkit/oncex` | Generic lazy-init (`OnceValue[T]`) |
| `toolkit/downloader` | HTTP file/blob downloader |

### Outbox Pattern (ADR-008)

All dual-writes (DB + Kafka) go through the outbox: write to `outbox_events` in the same DB transaction, then a background drainer publishes to Kafka and deletes committed rows. Never publish to Kafka directly from a service that also writes to the DB.

### LLM budget guard

Before any Anthropic API call, check `llm:disabled` in Redis. If `true`, skip the LLM call and return a cached or degraded response. The cron job resets the flag and accumulated spend at midnight UTC. Daily budget cap: `LLM_DAILY_BUDGET_USD` (default $5.00).

### Three-tier RCA cache

1. **L1** — Redis key `rca:{fingerprint}` (TTL 30 min)
2. **L2** — Postgres `rca_cache` table (same fingerprint, <24 h)
3. **L3** — fresh Claude Sonnet call (stores result in L1 + L2)

## Go Conventions (enforced project-wide)

**Receivers:** `h` for handlers, `s` for services, `r` for repositories.

**Imports:** stdlib → external packages → internal packages (three groups).

**Error wrapping:** `fmt.Errorf("failed to ...: %w", err)` — never swallow errors, never use global variables.

**GORM:** call `db.WithContext(ctx)` on every query — no exceptions. Wrap multi-step writes in a single transaction.

**Interfaces:** define the interface in `internal/contract/` before the concrete type; constructor injection always.

## Database Conventions

- `BIGSERIAL` primary keys (not UUIDs unless explicitly required by the proto).
- Use `gorm.Model` base struct for soft deletes (`deleted_at`).
- Column names are snake_case via GORM tags: `gorm:"column:service_name"`.
- Index required on every foreign key column, every `status` field, and every `fingerprint` column.
- TimescaleDB hypertables on `log_entries` and `anomaly_events` — partition by `created_at`.

## Architectural Constraints (project rules)

- **No LLM calls without budget check** — always verify `llm:disabled` in Redis first.
- **Always use Outbox for dual-writes** — never publish to Kafka directly inside a transaction.
- **No cross-service database access** — call other services via gRPC or events, never query their DB directly.
- **Idempotency** — retryable Kafka consumers must be safe to repeat (use upsert, not insert).
- **No business logic in handlers** — handlers validate input, delegate to service, return response.
- **No entity leakage** — handlers see only proto/DTO types; entities stay inside service + repository layer.

## Adding a new domain

1. Create `api/{domain}/{domain}.proto`, define gRPC + HTTP methods.
2. `make grpc` and `make validate`.
3. Add entity in `internal/types/entity/`, register with the GORM migrator.
4. Add repository in `internal/repository/`, expose via `RepositoryContext`.
5. Add service in `internal/service/`, then run `pmctl gen service` to regenerate `ServiceFactory`.
6. Add mapper in `internal/types/mapper/`.
7. Add handler in `internal/handler/`, register in `http_handler.go` / `grpc_handler.go`.
